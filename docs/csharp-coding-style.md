## C#项目开发规则
适用的开发语言：C#
代码文件扩展名：.cs

### 代码文件要求
- 所有类、枚举、接口，都要独立文件保存，不允许多个定义在同一个文件中。
- 文件名通常应与主类型名一致。


### 代码编写要求
1. 每行代码不要超过240个英文字符。
2. 函数参数定义时，优先在一行内定义，超出240个英文字符时，按参数定义为单元进行换行。
3. `if`、`switch`、`while`、`for` 的分支或循环代码必须使用大括号包裹，不允许省略大括号而编写单行代码。

### 代码结构要求
- 类（Class）定义时，要遵循以下代码块顺序：
1. 静态常量
2. 静态变量
3. 自有属性
	1. 私有属性
	2. 公开属性
4. 类方法
5. 自身实现
	1. 私有方法
	2. 公开方法
6. 事件节点，注意事件方法的定义要以did，will开头，明确事件发生的时机
7. 重载
8. 接口实现
9. 所有代码块都要使用如下格式进行包裹，方便阅读代码时定位跳转：
```
////////////////////////////////////////////////  
// @当前代码块名称
////////////////////////////////////////////////

#region 当前代码块名称

当前代码块代码

#endregion 
```

### Controller方法顺序要求

- Controller中编写方法时，应当从上至下按照“增、改、删、查、搜”的业务操作顺序排列。
- 同一方法同时承担新增和修改功能时，应放在删除、查询和搜索方法之前。
- 例如，内容标签Controller中的方法顺序应为：

1. `SaveContentTag`
2. `RemoveContentTags`
3. `GetContentTag`
4. `SearchContentTags`

### 模型转换要求
- “数据模型”和“视图模型”之间的转换代码，应写在转换源头模型类型对应的扩展方法类中。
- 转换方法命名格式为 `To目标模型类型`。
- 例如：数据模型 `Company` 转视图模型 `CompanyInfo`，应定义为 `CompanyExtension` 类中的扩展方法 `ToCompanyInfo`。
- 例如：视图模型 `CompanyInfo` 转数据模型 `Company`，应定义为 `CompanyInfoExtension` 类中的扩展方法 `ToCompany`。
- 控制器、服务或调用方中不应直接散落模型字段转换逻辑，应优先调用对应扩展方法。

### 命名规范
- C# 类名、结构体、枚举、接口方法、公共属性使用 PascalCase。
- 局部变量、方法参数使用 camelCase。
- 私有字段优先沿用所在项目现有风格；如无明显风格，使用 `_camelCase`。
- 接口名称以 `I` 开头。
- 异步方法以 `Async` 结尾。
- DTO / 请求 / 响应 / 配置类命名应表达用途，例如 `XxxDto`、`XxxRequest`、`XxxResponse`、`XxxOptions`。
- 常量名称优先沿用项目现有风格，不为了统一而改动无关常量。

### 模型类序列化要求
1. 当模型类的数据来源于JSON反序列化时，如：通过翻译第三方Api文档，编写模型类时，如果文档中数据属性的命名方式不符合C#属性命名规范，则需要按C#属性的命名规范进行属性定义，并通过`[JsonPropertyName]`特性标注属性在文档中的名称。
